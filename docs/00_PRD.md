# PRD — 미니홈피(가칭 mini-homepage)

## 1. 프로젝트 목적

싸이월드 미니홈피 감성의 **개인 미니홈피 웹 서비스**를 만든다. 사용자는 로그인 후 자신만의 미니홈피를 만들고, **다시 보고 싶은 URL · 나만의 앨범 사진 · 나만의 메모**를 한 곳에 저장한다. 동시에 **꾸미기 탭**에서 배경·색상·카드 모양·폰트와 **레이아웃·위젯 배치**를 직접 정해 본인 취향대로 공간을 완성한다.

본 서비스의 한 줄 정의:

> 나만의 URL 보관함, 앨범집, 메모장을 가지고 내 취향대로 꾸밀 수 있는 개인 미니홈피 웹 서비스.

초기 버전은 복잡한 SNS가 아니라 **단순한 개인 기록 보관 + 꾸미기 웹**으로 만든다.

## 2. 핵심 사용자

| 구분 | 설명 | 권한 |
|---|---|---|
| 운영자(본인) | 로그인한 미니홈피 소유자 | 자신의 데이터에 대한 CRUD 전체 |
| 익명 방문자 | `/u/[slug]`로 접속한 외부인 | **공개 상태일 때만** 읽기 전용 |

다중 사용자 협업, 친구, 팔로우 개념은 v1에 없다.

## 3. 핵심 기능 (v1)

1. **회원가입 / 로그인** — 이메일 + 비밀번호 자체 시스템(bcrypt, 쿠키 세션). Supabase Auth/소셜/매직링크 등 개별 인증은 도입하지 않는다.
2. **내 미니홈피 생성** — 고유 slug 발급, 기본 비공개(`is_public = false`).
3. **프로필 설정** — 닉네임, 한 줄 소개, 프로필 이미지, 미니홈피 제목.
4. **URL 보관함** — 제목·주소 입력. 추가/목록/수정/삭제. 카테고리 분류.
5. **앨범집** — 카테고리 기반. 기본 카테고리 자동 생성, 사용자 카테고리 추가/이름 수정/삭제. 사진 업로드/목록/삭제. 사진 설명은 선택.
6. **메모장** — 제목·내용. 작성/목록/상세/수정/삭제. 카테고리 분류.
7. **꾸미기 + 자유 캔버스** (핵심 차별점) — 배경색, 배경 이미지(업로드 + ON/OFF), 배경 무늬(8종), 포인트 색상, 글자 색상(배경·카드 배경은 그라데이션 지원), 카드 스타일(20종), 폰트(12종), 카드 투명도, 글자 크기(pt 직접 입력 + 프리셋). 카드는 **자유 캔버스**에서 드래그·리사이즈·z-index로 자유 배치하며(PC/태블릿), 모바일은 리스트형 폴백을 쓴다. PC/모바일 레이아웃은 2-track으로 분리 저장한다. 카드 종류는 프로필·URL·앨범·메모 + 텍스트 카드 + 그림판 카드이며, 카드 이름 편집과 카드/표시 카테고리 지정을 지원한다.
8. **미리보기** — 꾸미기 탭 내에서 더미 데이터로 즉시 시각 확인. 저장 전에는 서버 미반영.
9. **공개 미니홈피 페이지** `/u/[slug]` — 공개 상태일 때만 외부 노출. 사용자 꾸미기·레이아웃이 그대로 적용.
10. **관리자 페이지** — 홈, URL 보관함, 앨범집, 메모장, 꾸미기, 설정 6개 메뉴. 관리자 화면은 레이아웃 무관 고정 메뉴 사용.

## 4. 성공 기준

사용자가 다음 한 사이클을 막힘 없이 끝낼 수 있어야 한다.

1. 이메일/비밀번호로 회원가입.
2. 미니홈피 생성, 고유 slug 발급.
3. URL 3건 / 사진 3장(2 카테고리) / 메모 3건 등록.
4. 꾸미기 탭에서 배경·색·카드 스타일·폰트·글자 크기를 변경하고, 자유 캔버스에서 카드를 드래그·리사이즈로 배치 → 미리보기로 확인 → 저장.
5. 설정 탭에서 공개로 전환.
6. 시크릿/다른 브라우저로 `/u/[slug]` 접속 → 공개된 내용과 꾸미기·레이아웃이 정확히 노출.
7. 다시 비공개로 전환 → 외부 접속 차단(404 또는 비공개 안내) 확인.

## 5. 금지사항

- 미니홈피 기본 상태를 공개로 만들지 않는다. `is_public` 기본값은 `false`.
- 공개/비공개 검사를 프론트엔드에서만 처리하지 않는다. **반드시 서버/API에서 `is_public = true AND deleted_at IS NULL` 검증**.
- 다른 사용자의 데이터를 한 줄이라도 노출하지 않는다. 모든 조회·수정·삭제는 세션 사용자의 `user_id`로 검증한다.
- 사용자가 직접 삭제하지 않은 데이터를 자동으로 지우지 않는다. 휴면/오래된 데이터/이미지 자동 정리 기능을 만들지 않는다.
- 기존 기능명·탭명·API·DB 구조를 임의로 변경하지 않는다. 변경이 필요하면 `docs/12_DESIGN_CHANGE_REQUESTS.md`에 제안만 기록한다.
- 테스트를 실행하지 못한 항목을 "통과"로 표시하지 않는다.

## 6. 우선순위

| 순위 | 항목 | 비고 |
|---|---|---|
| 1 | 인증·사용자 데이터 분리·공개/비공개 정확성 | 어떤 화려한 기능보다 먼저 |
| 2 | URL · 앨범 · 메모 · 꾸미기 4축 CRUD | 본 서비스의 핵심 가치 |
| 3 | 미리보기·운영 편의(설정 탭, 백업 절차) | 사용성 마감 |

## 7. v1 제외 기능

아래 기능은 현재 범위에서 만들지 않는다.

- 방명록 / 방문자 수 / 좋아요 / 댓글
- 배경음악
- 친구 / 팔로우
- URL 썸네일 자동 가져오기 / URL 요약
- 메모 AI 정리 / RAG / 챗봇 등 AI 기능 전반
- 자유형 태그 / 전역 검색 (※ URL·메모·앨범·카드의 카테고리 분류는 §3에 반영되어 구현됨)
- 앨범별·메모별 세부 공개 설정
- 알림 / 결제

AI 기능은 추후 별도 Phase로 도입한다. 도입 시 `docs/ai/` 폴더를 새로 추가한다.

> **v1 원안 대비 변경**: 초기 PRD v0.1은 "드래그앤드롭 꾸미기"를 제외 항목으로 두고 슬롯 기반 레이아웃(single/double)을 채택했으나, v0.5~v0.9.1 진화 과정에서 자유 캔버스(드래그·리사이즈·z-index) + 카테고리 분류로 전환되었다. 변경 근거는 `docs/12_DESIGN_CHANGE_REQUESTS.md` DCR-20260519-03 참조.

## 8. 기술 방향 요약 (상세는 `docs/01_ARCHITECTURE.md`)

- Next.js (App Router, TypeScript) + Tailwind CSS
- Supabase Postgres (DB) + Supabase Storage (이미지)
- 자체 인증(bcrypt + 서버 쿠키 세션). Supabase Auth 미사용.
- 배포: Vercel + Supabase 개발/운영 프로젝트 분리
