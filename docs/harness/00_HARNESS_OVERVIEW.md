# 하네스 개요

본 미니홈피 프로젝트의 13종 하네스를 한 곳에서 안내한다.

| # | 하네스 | 목적 | Phase |
|---|---|---|---|
| 1 | 단위 테스트 | 순수 함수 / service / validator 단위 검증 | 2~10 |
| 2 | API/DB 통합 | Route Handler ↔ DB 통합 | 2~10 |
| 3 | UI 흐름 | 9개 화면의 사용자 흐름 | 4~10 |
| 4 | 회귀 | 기존 기능 유지 확인 | 7~10 |
| 5 | 보안/개인정보 | **데이터 분리·공개/비공개·인증/세션·키 노출 방지** | 2~10 |
| 6 | 설계 준수 | 설계문서 밖 기능 차단 | 1~10 |
| 7 | 단위화 | 디렉터리 책임·의존성 방향 | 1~10 |
| 8 | 문서 관리 | 헤더/버전/MASTER_INDEX 일관성 | 0~10 |
| 9 | 오류 응답 | 응답 포맷·코드 카탈로그 일관성 | 2~10 |
| 10 | 기능 목록 | FEATURE_CATALOG 갱신 | 0~10 |
| 11 | 실행형 Phase/Step | phases/ JSON 상태 일관성 | 0~10 |
| 12 | Claude Hooks | `.claude/settings.json` hook 동작 | 0~10 |

게이트 12·13(Codex 위임)은 v1 미사용. 추후 Codex 도입 시 활성화한다.

각 Phase의 필수 하네스는 [`docs/05_HARNESS_PLAN.md`](../05_HARNESS_PLAN.md) §2 표를 참조.

## 실행 모드

- v1은 **수동 실행 모드**. Python 자동화 스크립트(`scripts/harness_*.py`)는 만들지 않는다.
- 각 하네스 문서의 체크리스트를 Claude Code 또는 사람이 직접 점검하고 `docs/08_VALIDATION_LOG.md`에 결과 기록.
- 추후 자동화 필요 시 별도 Phase로 도입한다.
