# API / DB 통합 하네스

Route Handler ↔ Supabase 통합 동작을 검증한다.

## 1. 환경

- 별도의 **테스트용 Supabase 프로젝트**(또는 분리된 스키마) 사용 권장. 운영 DB 접근 금지.
- 환경변수: `NEXT_PUBLIC_SUPABASE_URL_TEST`, `SUPABASE_SERVICE_ROLE_KEY_TEST` 등 별도. 운영 키 절대 사용 금지.
- 각 테스트 전에 트랜잭션 롤백 또는 fixture truncate.

## 2. 필수 케이스 (TC 매핑은 `docs/06_TEST_CASES.md`)

### 인증
- [ ] TC-AUTH-001~006 통과
- [ ] 응답 포맷이 §18을 따르는가 (모든 응답 검사)

### 미니홈피
- [ ] TC-HP-001~004 통과
- [ ] 생성 트랜잭션이 atomic — 카테고리 생성 실패 시 미니홈피 자체도 롤백되는가

### URL / 앨범 / 메모
- [ ] TC-URL-* / TC-ALB-* / TC-MEMO-* 통과
- [ ] 모든 조회가 `deleted_at IS NULL`을 부착하는가 (의도적으로 deleted 데이터를 만들고 조회 후 미포함 확인)
- [ ] 모든 자원이 `user_id` 검증을 거치는가 — TC-ISO-* 시리즈로 검증

### 꾸미기 / 레이아웃
- [ ] TC-DEC-* / TC-LAYOUT-* 통과
- [ ] `PUT /api/decorate`가 `layout_slots`를 서버 검증하는가
- [ ] 잘못된 슬롯/위젯/모드를 정확한 코드로 거절하는가

### 공개 페이지
- [ ] TC-PUB-001~007 통과
- [ ] `/api/public/[slug]`가 비공개/미존재를 동일 응답으로 처리하는가 (`HOMEPAGE_PRIVATE_OR_NOT_FOUND` 404)
- [ ] 응답에 비밀번호 해시·이메일·다른 사용자 정보가 포함되지 않는가

### 사용자 데이터 분리
- [ ] TC-ISO-001~006 모두 통과
- [ ] A로 로그인한 상태에서 B의 자원 id로 모든 메서드를 시도 — 모두 404/403

## 3. 회귀 보호

- [ ] 기존 테스트가 통과 상태 유지
- [ ] 추가된 컬럼/엔드포인트가 기존 응답 키를 깨지 않음

## 4. 체크리스트

- [ ] 테스트가 운영 DB가 아닌 격리 환경에서 실행되는가?
- [ ] 각 테스트가 독립적인가(다른 테스트 결과에 의존하지 않음)?
- [ ] 서비스 롤 키가 코드에 하드코딩되지 않았는가?
- [ ] 실패한 테스트가 `docs/08_VALIDATION_LOG.md`에 기록되는가?
